# Self-hosting Inuberry

> **Installing the published image?** Follow the step-by-step guide at https://crm.inuberry.com/docs/self-hosting (Docker image, one-click updates). This file is for building and running Inuberry from this repository.

Inuberry runs anywhere that runs Node 22 (Docker or plain Node), with a Supabase database
(Supabase Cloud, or Supabase's self-hosted Docker stack). You own the server and all of the data.

You need:
- a Supabase project (Postgres + Auth). Plain Postgres is not enough: Inuberry uses Supabase Auth,
  its REST API and row-level security.
- `psql` (PostgreSQL client) and `bun` on the machine you run the setup from.
- for Docker: Docker 24+.

## 1. Create the database
1. Create a Supabase project (or start the self-hosted stack:
   https://supabase.com/docs/guides/self-hosting/docker).
2. Copy the connection string: Supabase → Project Settings → Database → Connection string (URI).
3. From a checkout of this repository:
   ```bash
   bun install
   DATABASE_URL="postgresql://postgres:<password>@<host>:5432/postgres" bun run db:migrate
   ```
   This applies every migration in order and records them, so you can run it again after each upgrade.

## 2. Configure
```bash
cp .env.example .env
```
Fill in at least the Supabase values, `SITE_URL`, and `APP_ENCRYPTION_KEY`
(`node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`).
Every setting is explained in `.env.example`.

In Supabase → Authentication:
- **URL configuration:** Site URL = your `SITE_URL`; add `SITE_URL/**` to the redirect URLs.
- **SMTP settings:** your mail server, so sign-up, invite and password-reset emails are delivered.
- **Email templates:** paste the HTML from `deploy/email-templates/` (generated by `bun run email:templates`).
- **Google sign-in (optional):** Providers → Google, with your Google OAuth client; set `VITE_OAUTH_MODE=native`.

## 3a. Run with Docker (AWS, Google Cloud, any VM)
```bash
docker compose up -d --build
```
The app listens on port 3000 (`PORT` in `.env`). Put it behind your load balancer or a reverse proxy
with HTTPS (Caddy, nginx, AWS ALB, Google Cloud Run).

- **AWS:** an EC2 instance with Docker, or ECS/Fargate with the image pushed to ECR.
- **Google Cloud:** Cloud Run (build with `gcloud builds submit`, pass the `VITE_*` build args) or a Compute Engine VM.

## 3b. Run without Docker
```bash
bun run build:node
bun run start          # node .output/server/index.mjs, reads PORT and the server env vars
```

## 4. First admin
1. Open the app and sign up with your email. Confirm it.
2. ```bash
   DATABASE_URL="…" ADMIN_EMAIL="you@company.com" bun run db:bootstrap
   ```
   Your account now opens the platform console at `/app/platform`.

## Stripe (optional, for selling plans)
1. Stripe → Developers → API keys: put the secret key in `STRIPE_SECRET_KEY`, the publishable key in
   `VITE_STRIPE_PUBLISHABLE_KEY` (rebuild after changing it).
2. Stripe → Developers → Webhooks → Add endpoint: `https://<your domain>/api/public/payments/webhook`,
   events `checkout.session.completed`, `customer.subscription.created`, `customer.subscription.updated`,
   `customer.subscription.deleted`, `invoice.payment_failed`, `charge.succeeded`, `charge.failed`.
   Put its signing secret in `STRIPE_WEBHOOK_SECRET`.

## Upgrading
When the platform console shows **Update available**:
1. **Back up the database** (Supabase → Database → Backups, or `pg_dump "$DATABASE_URL" > backup.sql`).
2. ```bash
   git fetch --tags && git checkout v<new version>
   bun install
   DATABASE_URL="…" bun run db:migrate
   docker compose up -d --build          # or: bun run build:node && bun run start
   ```
3. If anything goes wrong: check out the previous tag, rebuild, and restore the backup.

Release notes are in `CHANGELOG.md` and on the GitHub releases page.
